## Goal

An authorized user can open a project's results page and understand its most recently opened feedback cycle through exact dates, response count, average score, a complete 1–5 distribution, and anonymous comments. Projects with no cycles or no responses have useful, non-error empty states.

## Acceptance criteria

- [ ] Opening `/dashboard/project/<project-id>/` for an authorized project displays the project's full name and a page visibly titled “Weekly health”.
- [ ] When a project has multiple cycles, the page shows the cycle with the greatest `opens_at` timestamp, regardless of whether that cycle is future, open, or closed; if cycles share the same opening timestamp, the cycle with the greatest database ID is selected.
- [ ] The selected cycle's opening and closing dates are both visibly displayed in the configured local timezone, including day, month, and year so the range is unambiguous.
- [ ] The displayed response count equals exactly the number of responses belonging to the selected cycle and excludes responses from every other cycle.
- [ ] The displayed average equals the arithmetic mean of scores belonging to the selected cycle, rounded to one decimal place using normal numeric rounding and without changing stored scores.
- [ ] The score distribution visibly contains all five score labels `1`, `2`, `3`, `4`, and `5`, each paired with its exact response count; score values with no responses display `0`.
- [ ] The five distribution counts add up to the displayed response total.
- [ ] Only non-blank comments from responses in the selected cycle are displayed; comments from older or newer non-selected cycles are absent.
- [ ] Displayed comments are ordered newest-created-first; comments with equal creation timestamps are ordered by descending database ID.
- [ ] Each displayed comment is visibly identified as anonymous and may show its response score and submitted date, but never a participant identity or duplicate-prevention identifier.
- [ ] Comment text containing HTML-like content is shown as text and cannot create executable markup on the page.
- [ ] For a selected cycle with no responses, the page still shows its dates, response count `0`, average-score placeholder `—`, five distribution counts of `0`, and a visible “No comments yet” message.
- [ ] For a selected cycle with scored responses but only empty or whitespace-only comments, its score metrics remain visible and the comments section displays “No comments yet”.
- [ ] For an authorized project with no feedback cycles, the route returns HTTP status `200`, visibly names the project, states “No feedback cycles yet”, and does not show fabricated dates, averages, response counts, or distribution data.
- [ ] Authorized users can view results for an inactive project as established by [#6](https://github.com/hadiheib99/weekly-feedback-app/issues/6), and the page visibly identifies that the project is inactive.
- [ ] Unauthorized and nonexistent project IDs retain the identical non-disclosing `404` behavior established by [#6](https://github.com/hadiheib99/weekly-feedback-app/issues/6).
- [ ] The page never displays a response's `network_hash` or `device_hash`, a cycle's public token, or a public feedback URL.
- [ ] Automated tests visibly cover deterministic latest-cycle selection, future/open/closed latest cycles, exact dates, response count, decimal average, all five distribution buckets including zeros, distribution sum, cross-cycle exclusion, comment filtering and ordering, escaped comment content, zero responses, blank-only comments, no cycles, inactive projects, authorization, and private-field absence.

## Out of scope

- Sign-in, project authorization, and missing-versus-unauthorized project behavior are handled in [#6](https://github.com/hadiheib99/weekly-feedback-app/issues/6).
- The multi-project overview and its all-cycle aggregates are handled in [#7](https://github.com/hadiheib99/weekly-feedback-app/issues/7).
- Creating or editing projects and cycles, assigning leads, and administrative response inspection are handled in [#9](https://github.com/hadiheib99/weekly-feedback-app/issues/9).
- Demonstration cycles, responses, and comments are handled in [#10](https://github.com/hadiheib99/weekly-feedback-app/issues/10).
- Full keyboard, screen-reader, color-contrast, chart semantics, and small-screen verification are handled in [#11](https://github.com/hadiheib99/weekly-feedback-app/issues/11).
- Cycle switching, historical trend charts, comparisons, comment moderation, sentiment analysis, exports, and downloadable reports are deferred limitations documented in [#12](https://github.com/hadiheib99/weekly-feedback-app/issues/12).
- Editing or deleting submitted feedback and revealing participant identities are not part of the MVP and are documented in [#12](https://github.com/hadiheib99/weekly-feedback-app/issues/12).

## Constraints

- Keep implementation changes inside the project-results query/context in `feedback/views.py`, the results template under `templates/feedback/`, existing feedback styles only where necessary, and focused automated tests under `feedback/`.
- Use the models and ordering fields established by [#2](https://github.com/hadiheib99/weekly-feedback-app/issues/2) and the reusable authorization policy established by [#6](https://github.com/hadiheib99/weekly-feedback-app/issues/6).
- Select exactly one cycle using deterministic database ordering: `opens_at` descending and then ID descending. Do not combine responses from multiple cycles on this page.
- Compute count, average, and distribution using Django ORM aggregation. Avoid one query per response and do not calculate aggregates from values rendered in the template.
- Use Django timezone and template date facilities with the project's configured timezone. Do not compare availability to decide which cycle is latest.
- Treat a comment as displayable only if it contains at least one non-whitespace character. Escape all participant-supplied comment content with Django's default template autoescaping.
- Preserve the authorization and non-disclosure rules from [#6](https://github.com/hadiheib99/weekly-feedback-app/issues/6). Never pass hashes, device/network values, or public cycle tokens to the results template.
- Do not add dependencies, change the schema, create migrations, alter public submission behavior, or build export/history controls in this task.
- Follow [`AGENTS.md`](https://github.com/hadiheib99/weekly-feedback-app/blob/master/AGENTS.md), [`_docs/process.md`](https://github.com/hadiheib99/weekly-feedback-app/blob/master/_docs/process.md), and [`_docs/task-template.md`](https://github.com/hadiheib99/weekly-feedback-app/blob/master/_docs/task-template.md).
