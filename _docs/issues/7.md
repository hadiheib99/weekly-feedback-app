## Goal

Each signed-in user has a project overview showing every active project they are authorized to view, with accurate all-cycle response totals and average health scores. The overview offers clear links to project results and an informative empty state without leaking unauthorized or inactive projects.

## Acceptance criteria

- [ ] Opening `/dashboard/` while authenticated displays a page visibly titled “Project overview” with one project row for each active project the user may view under the authorization policy from [#6](https://github.com/hadiheib99/weekly-feedback-app/issues/6).
- [ ] A non-staff lead sees each active project assigned to that user exactly once and sees no unassigned project.
- [ ] A staff administrator sees every active project exactly once whether or not the administrator is assigned as a lead.
- [ ] Inactive projects do not appear in this overview for either leads or staff administrators, although direct authorized historical access remains governed by [#6](https://github.com/hadiheib99/weekly-feedback-app/issues/6).
- [ ] Every displayed project row visibly contains the project's full name, total response count across all of that project's feedback cycles, and average score across those same responses.
- [ ] A project with responses in multiple open, future, and closed cycles displays a response count and average calculated from all stored responses across all cycles; no response is counted more than once.
- [ ] Average scores are displayed rounded to one decimal place using normal numeric rounding, without changing the stored scores.
- [ ] A project with cycles but no responses and a project with no cycles each display a response count of `0` and an average-score placeholder of `—`, not `0`, `None`, or a blank cell.
- [ ] Each project name is a working link to `/dashboard/project/<project-id>/` for that same project.
- [ ] Project rows are ordered alphabetically by project name without case affecting the order; projects with names equal ignoring case are ordered by ascending database ID.
- [ ] When an authenticated non-staff user has no active assigned projects, the page visibly states “No active projects are assigned to this account” and shows no project rows.
- [ ] When a staff administrator has no active projects to view, the page visibly states “No active projects are available” and shows no project rows.
- [ ] The page does not display any response comment, individual score, network hash, device hash, or public cycle token.
- [ ] Aggregate queries remain correct for a project with multiple assigned leads and do not multiply its response count because of lead relationships.
- [ ] Automated tests visibly cover lead filtering, staff visibility, inactive-project exclusion, deterministic ordering, one row per project, multiple cycles, exact count and average calculations, zero-response/no-cycle placeholders, multiple leads, both role-specific empty states, detail links, and absence of response-level/private metadata.

## Out of scope

- Sign-in, sign-out, anonymous redirects, the reusable authorization policy, and direct project-access decisions are handled in [#6](https://github.com/hadiheib99/weekly-feedback-app/issues/6).
- The project-results page, latest-cycle selection, score distribution, response-level comments, and results empty states are handled in [#8](https://github.com/hadiheib99/weekly-feedback-app/issues/8).
- Creating or editing projects, assigning leads, and any “New project” control are handled through the administration work in [#9](https://github.com/hadiheib99/weekly-feedback-app/issues/9).
- Demonstration projects, cycles, responses, users, and credentials are handled in [#10](https://github.com/hadiheib99/weekly-feedback-app/issues/10).
- Full keyboard, screen-reader, color-contrast, and small-screen verification of the overview is handled in [#11](https://github.com/hadiheib99/weekly-feedback-app/issues/11).
- Trends, comparisons between weeks, alerts, exports, search, filters, pagination, and portfolio analytics are deferred limitations documented in [#12](https://github.com/hadiheib99/weekly-feedback-app/issues/12).

## Constraints

- Keep implementation changes inside the overview query/context in `feedback/views.py`, the overview template under `templates/feedback/`, existing feedback styles only where necessary, and focused automated tests under `feedback/`.
- Use the models and relationships established by [#2](https://github.com/hadiheib99/weekly-feedback-app/issues/2) and the reusable visibility policy established by [#6](https://github.com/hadiheib99/weekly-feedback-app/issues/6); do not duplicate authorization logic in the template.
- Apply `Project.is_active=True` specifically to the overview after authorization. Do not change the broader direct-access policy from [#6](https://github.com/hadiheib99/weekly-feedback-app/issues/6).
- Compute response count and average with Django ORM aggregation. Do not calculate project aggregates by issuing one query per displayed project or by iterating over all responses in Python.
- Aggregate every stored response belonging to the project, regardless of cycle availability; cycle-specific presentation belongs to [#8](https://github.com/hadiheib99/weekly-feedback-app/issues/8).
- Render plain text safely through Django templates. Do not expose response-level records or duplicate-prevention identifiers in this overview.
- Do not add dependencies, change the data schema, create migrations, alter authentication behavior, or implement project-results calculations in this task.
- Follow [`AGENTS.md`](https://github.com/hadiheib99/weekly-feedback-app/blob/master/AGENTS.md), [`_docs/process.md`](https://github.com/hadiheib99/weekly-feedback-app/blob/master/_docs/process.md), and [`_docs/task-template.md`](https://github.com/hadiheib99/weekly-feedback-app/blob/master/_docs/task-template.md).
