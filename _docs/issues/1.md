## Goal

A developer cloning the repository can install its declared dependencies, initialize an empty Django database, start the development server, and run at least one passing automated smoke test by following the repository documentation.

## Acceptance criteria

- [ ] The repository root visibly contains `manage.py`, `requirements.txt`, the Django project package, the feedback app package, and setup instructions in `README.md`.
- [ ] The Django project package's `settings.py` visibly lists the feedback app in `INSTALLED_APPS`.
- [ ] Following the documented install and migration commands from a fresh clone completes without an error shown in the terminal.
- [ ] Running the documented development-server command shows Django starting successfully and displays a local server URL in the terminal.
- [ ] Opening that local URL displays a rendered application page rather than a Django configuration error or an unhandled exception.
- [ ] Running `python manage.py test` visibly reports at least one test run and an `OK` result in the terminal.
- [ ] Running the test command against a newly initialized, empty database still visibly reports `OK`; the smoke test does not depend on demo records or manually created users.
- [ ] `README.md` visibly documents prerequisites, environment setup, dependency installation, database migration, server startup, and the test command in copyable code blocks.
- [ ] The repository does not visibly contain committed virtual-environment directories, Python cache files, local secret files, or generated test databases.

## Constraints

- Keep changes within the initial Django scaffold, feedback app scaffold, `requirements.txt`, `README.md`, `.gitignore`, and the smoke-test file; do not implement product features or data models in this task.
- Use Django and Python dependencies declared in `requirements.txt`; do not add another web framework or test runner.
- Use Django's built-in test command: `python manage.py test`.
- The setup instructions must work from a fresh clone without relying on files outside the repository or undocumented environment variables.
- Do not commit credentials, secret keys intended for production, local databases, virtual environments, or generated cache files.
- Follow the project backlog in [`_docs/tasks.md`](https://github.com/hadiheib99/weekly-feedback-app/blob/master/_docs/tasks.md) and the task format in [`_docs/task-template.md`](https://github.com/hadiheib99/weekly-feedback-app/blob/master/_docs/task-template.md).
